# DAW で使うときの保存とオートメーション

プラグイン（VST3・CLAP）を DAW に挿したとき、音色やエフェクトの設定をどうプロジェクトに残し、
曲の進行に合わせてどう動かすか。

## 1. 状態の保存

プロジェクトを保存すると、プラグインは次のものを入れる（VST3 の `getState`、CLAP の `state.save`。並びは両方同じ）。

| 版 | 中身 |
|---|---|
| 1 | 出力レベル |
| 2 | **機械まるごと**（CPU・RAM・SWP30・LCD。詰めて 30 万バイトほど） |
| 3 | 差している SmartMedia のファイルの場所（中身は入れない） |
| 4 | **XG の値だけの控え**（6KB ほど） |

開き直すと機械まるごとの状態を戻すので、画面で作った音色もエフェクトも NVRAM も、保存した時点の姿に戻る。

### XG の値だけの控え（版 4）

機械まるごとの状態は、S-MU2000 の版が変わって中身の並びが変わると読めなくなる。
そのときの予備として、XG の値（システム・リバーブ／コーラス／バリエーション・インサーション 1-4・
マスター EQ・64 パート）を、**別の機械に流し込めば同じ設定になる MIDI** の形で一緒に入れておく
（`src/ui/xg_state.h` の `setup_messages`）。機械まるごとの状態が読めなかったときだけ、
これを MIDI IN A へ流して戻す（数 KB なので 31250bps の直列で 2 秒ほどかかる）。

流し方は firmware で確かめて決めた。

* 塊ごとに一括ダンプ（`F0 43 0n 4C 数 数 番地 中身 和 F7`）で流す
* エフェクト（`02 01 00/20/40`・`03 0n 00`）とマスター EQ（`02 40 00`）は、先頭の**種類を書くと firmware が
  中身を種類の既定値に書き戻す**。種類はパラメータチェンジで先に送り、残りをその次の番地から一括ダンプで流す
* パートの EQ（`08 pp 72-77`）は一括ダンプでは周波数が入らない。1 つずつパラメータチェンジで送る
* 全部を間を空けずに続けて流してよい

起動しただけの機械へ、PHAZE1.mid の頭で変えた値（94 か所）を流し込むと、違いは 1 か所
（コーラスの `02 01 2B`）まで戻る。

## 2. オートメーション

### 名前付きの XG の値

XG の値を名前付きのパラメータとしてホストに見せる（`src/vst3/automation.h`）。
ホストのオートメーションのレーンで描いても、記録してもよい。VST3 と CLAP で表も番号も同じ。

**パート（64 × 19 本）** 名前は `A1 Volume` のように、パート名 + 値の名前。

| k | 値 | 音源への入れ方 |
|---|---|---|
| 0 | Volume | CC7 |
| 1 | Pan | CC10（0 のランダムはパラメータチェンジ） |
| 2 | Reverb Send | CC91 |
| 3 | Chorus Send | CC93 |
| 4 | Var Send | CC94（バリエーションの接続が SYSTEM のときだけ。INSERTION ならパラメータチェンジ） |
| 5 | Cutoff | CC74 |
| 6 | Resonance | CC71 |
| 7 | Attack | CC73 |
| 8 | Decay | CC75 |
| 9 | Release | CC72 |
| 10 | Vib Rate | CC76 |
| 11 | Vib Depth | CC77 |
| 12 | Vib Delay | CC78 |
| 13-16 | EQ Bass Gain / Bass Freq / Treble Gain / Treble Freq | パラメータチェンジ |
| 17 | Dry Level | パラメータチェンジ |
| 18 | Note Shift | パラメータチェンジ |

**マスター（27 本）** Master Volume・Master Tune・Transpose、Reverb Return・Reverb Pan・Chorus Return・Chorus Pan・
Chorus to Reverb・Var Return・Var Pan・Var to Reverb・Var to Chorus、Master EQ Gain 1-5・Freq 1-5・Q 1-5。
どれもパラメータチェンジ。

**インサーション 1-4 のパラメータ 1-16（4 × 16 本）** 名前は `INS1 Param 1` 〜 `INS4 Param 16`。
パラメータの意味と範囲はインサーションの種類で変わる（xg/fx_params.h。LCD の編集画面で調べた表）ので、
**そのときの種類の範囲に対する割合**を 0-1000 で持つ（0 が下の端、1000 が上の端。VST3 は目盛りの無い 0-1）。
表示はそのときの種類の名前と書式で `Drive 64`、`LchDelay 371.6`、`Dry/Wet D<W63` のように出し、その形で打ち込んでもよい。
音源へは、そのときの種類の範囲に当てはめたパラメータチェンジ（`03 0n xx`。1 バイトの種類は 02-0B、2 バイトの種類は 30-43、
11-16 は 20-25）で入れる。種類がそのパラメータを持たなければ何も送らない。種類を替えると、同じ割合でも中身は別物になる。

**番号は保存した曲が覚えているので動かさない。** パート pp（0-63）の k 番目が `65536 + pp × 32 + k`、
マスターの k 番目が `67584 + k`、インサーション b（0-3）のパラメータ n が `67648 + b × 16 + n - 1`。
足すときは空いている所に。VST3 は `XG Part A1`〜`XG Part D16`・`XG Master`・`XG Insertion 1`〜`4` のユニットに、
CLAP は `Parts/Part A1`〜・`Master`・`Insertion 1`〜`4` のモジュールに分けてある。

値は XG の値そのもの（例えば Cutoff は 0-127 で 64 が音色のまま、EQ の周波数は表の番号）。
VST3 はそれを 0-1 に畳んで渡す。表示は `80 Hz`、`+6 dB`、`L24`、`+5.5 cent` のような形で、
その形で打ち込んでもよい。

### CC で入れる理由

パラメータチェンジ（SysEx）だと、LCD の音色アイコンに Ex の印が出る。CC で同じことができる値は CC で入れる。
上の表の CC は、firmware で「CC を送るとパートの XG の値が同じ数になる」ことを 0・1・20・64・100・127 で確かめた
（口 A と B のどちらのパートでも）。

CC はチャンネルの全パートに効くので、**パートの受信チャンネルがそのパートだけのもの**のときだけ使う。
チャンネルが OFF や他のパートと共有なら、パラメータチェンジにする。

### 同じ値は送らない

ホストはオートメーションの値を区間ごとに送り続けることがある。全部を音源へ流すと 31250bps の直列が溢れるので、

* 最後に送った値と同じで、送ってから 0.5 秒以内なら送らない
* 0.5 秒より前に送った値でも、音源の RAM の値がもう同じなら送らない（曲や画面が先に入れた）

### 画面で触った値をホストへ

プラグインの画面（パネルのエディタの面、PC の窓。インサーションの設定の窓のつまみも）で XG の値を触ると、ホストへ伝える。
DAW がオートメーションを書き込む状態なら、そのまま記録される。

* VST3: `beginEdit` → `performEdit`（動かすたび）→ `endEdit`
* CLAP: `CLAP_EVENT_PARAM_GESTURE_BEGIN` → `CLAP_EVENT_PARAM_VALUE` → `CLAP_EVENT_PARAM_GESTURE_END`
  （画面の糸で溜め、`request_flush` でホストに取りに来てもらう）

つまみを離したことは画面の層からは分からないので、**0.4 秒触られなかったら操作の終わり**とみなす。
画面を閉じたときは全部終える。仕組みは `xg::model` の `set_edit_listener`（書いたときだけ呼ばれ、
RAM から読んだ値では呼ばれない。インサーションのパラメータは `set_raw` の `set_raw_listener`）→ `engine::notify_edit` → プラグイン。

ホストに見せる値は、触ってから 1 秒は触った値、それより後は音源の RAM の写しから読む。
曲の SysEx やパネルで値が変わっても、ホストが値を聞けば今の値が返る（ホストの表示を自分から
更新させるのは、状態を戻したときだけ。VST3 の `restartComponent(kParamValuesChanged)`、CLAP の `rescan`）。

### MIDI トラックで動かす

今までどおり、MIDI クリップに CC・NRPN・SysEx を書いて動かしてもよい。VST3 では CC 0-127・プレッシャ・
ベンド・プログラムチェンジを、口 × チャンネルごとの隠しパラメータとして受ける（doc/vst3.md）。

オートメーションのレーンと曲の SysEx が同じ値を動かすと、後から来た方が勝つ。

## 3. 確かめ方

```
build/vst3probe.exe build/S-MU2000.vst3/Contents/x86_64-win/S-MU2000.vst3 --automation
build/clapprobe.exe build/S-MU2000.clap --automation
```

1. パラメータを全部並べ、番号が重ならないことと、表示と打ち込みが往復することを見る
2. CC で入る値（A1 Cutoff・A10 Attack・D16 Volume）とパラメータチェンジで入る値（A1 EQ Bass Gain・B3 Pan のランダム・
   Reverb Return・Master EQ Gain 3・C5 Note Shift・Master Tune）、インサーションのパラメータ（1 を DISTORTION、2 を DELAY LCR に
   してから INS1 Param 1・INS2 Param 1・INS2 Param 10）を、同じ値を区間ごとに 2 秒送り続けてから、
   音源の RAM から読み戻して合うかを見る（CLAP は音を作っていないときの `flush` で入れた値も）
3. 状態を保存して別の実体に戻し、同じ値になるかを見る
4. 状態から機械まるごとを抜いて XG の値の控えだけにし、それで戻るかを見る

画面の操作は `vst3probe ... --view 30` で窓を出し、パネルのエディタの面のつまみを回すと、
`beginEdit` / `performEdit` / `endEdit` が出る（Cutoff を上へドラッグして、beginEdit 1・performEdit 23・endEdit 1 を確かめた）。
カードの差し込み口を右クリックして一覧を開き、INS 1 をダブルクリックしてインサーションの設定の窓で Drive を回すと、
`INS1 Param 1`（67648）で beginEdit 1・performEdit 13・endEdit 1 が出た。

## まだ無いもの

* システムエフェクト（リバーブ・コーラス・バリエーション）の中身（パラメータ 1-16）と、エフェクトの種類のオートメーション
* 音色（バンク・プログラム）のオートメーション（今は MIDI のプログラムチェンジで）
* Audio Unit（macOS）への同じ仕組み
* 実際の DAW（Cubase・REAPER・Bitwig など）で記録と再生を試すこと。ここまでは DAW 無しの小さなホストで確かめただけ
