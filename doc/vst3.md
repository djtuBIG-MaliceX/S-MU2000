# VST3 プラグイン

`S-MU2000.vst3` は MU2000 をそのまま DAW に挿すためのもの。画面は持たない。
音の作り方は `live.exe` と同じで、**ホストが要求した分だけ音源を進める**。

```
make                exe と一緒にバンドルも作る
make vst3           バンドルだけ（build/S-MU2000.vst3/）
make install-vst3   それを VST3 の置き場へ複製する（管理者権限が要ることがある）
make probe          DAW 無しで読み込みを確かめる
```

## 置き場と ROM

バンドルの形は VST3 の決まりどおり。

```
S-MU2000.vst3/
  Contents/
    x86_64-win/
      S-MU2000.vst3      ← 中身は DLL
    Resources/
      roms.txt           ← ROM の場所を書いた紙（後述）
```

Windows でホストが見に行く場所は 2 つ。

| 場所 | 誰のもの |
|---|---|
| `%LOCALAPPDATA%\Programs\Common\VST3` | その利用者だけ。管理者権限が要らない |
| `C:\Program Files\Common Files\VST3` | 全員 |

ROM は同梱できない（利用者が自分の実機から吸い出したもの）ので、プラグインは
起動時に次の順で探す。**最初に `mu2000_flash.bin` が見つかった場所**を使う。

1. 環境変数 `S_MU2000_ROMS`
2. `<バンドル>/Contents/Resources` と その下の `roms`
3. DLL のすぐ横、および `<DLL の横>/roms`
4. `Contents/Resources/roms.txt` または `<DLL の横>/roms.txt` の 1 行目に書かれた場所
5. `%LOCALAPPDATA%\S-MU2000\roms`
6. `%USERPROFILE%\Documents\S-MU2000\roms`

ROM は 36MB あるので複製したくない。**`roms.txt` に場所を 1 行書くのが楽**。

```
C:\Users\あなた\GitHub\MU2000\roms
```

うまく読めたか、どこを探したかは `%LOCALAPPDATA%\S-MU2000\log.txt` に残る。
画面を持たないので、鳴らないときはまずこれを見る。止めたときには
CPU 使用率と 1 ブロックあたりの最悪時間も書く。

## 起動待ち

MU2000 は電源を入れてから受信を始めるまでに、音にして約 2 秒（実時間で 2 秒弱）
かかる。実機と同じで、ここを待たずに MIDI を流すと音色指定が捨てられて全部ピアノになる。

プラグインは読み込まれた時点で別スレッドで起動を始め、終わるまでは無音を返す。
その間に届いた MIDI は溜めておき、起動が済んでからまとめて流す。
**DAW に挿してすぐ弾くと数秒間鳴らない**が、これは実機の電源投入と同じ。

## 糸（スレッド）

音を作るのは DAW の音声の糸だが、SWP30 のスレーブ（MU2000 の 2 つ目の音源チップ）だけは
**プラグインが自分で作る糸**で回す（1 枚あたり 2 コアを使い、2 割ほど速い）。挿した枚数が論理コア数の
1/4 を超えると、自動で 1 本に戻す。

DAW が管理していない糸が増えるのを嫌う場合や、コアの割り振りを DAW に任せたい場合は、
`%LOCALAPPDATA%\S-MU2000\plugin.ini`（macOS は `~/Library/Application Support/S-MU2000/plugin.ini`）に
次の 1 行を書くと、スレーブも DAW の音声の糸の中で回す（出る音は同じ）。VST3・CLAP・AU で共通。

```
threaded=0
```

挿し直す（プロジェクトを開き直す）と効く。効いたときは記録（log.txt）に 1 行出る。

## MIDI の受け取り方

VST3 は MIDI をそのままでは渡してこない。2 通りに分かれる。

| MIDI | VST3 での渡され方 |
|---|---|
| ノートオン／オフ、ポリプレッシャ、システムエクスクルーシブ | イベント（`IEventList`） |
| コントロールチェンジ、ピッチベンド、チャンネルプレッシャ、プログラムチェンジ | **パラメータ変化**（`IParameterChanges`） |

後者を受け取るには `IMidiMapping` で「チャンネル × 番号 → パラメータ番号」を
ホストに教える必要がある。そのため 16 チャンネル × 131 種類 = 2096 個の
パラメータを名乗っている（一覧に出ないよう `kIsHidden` を立ててある）。

受け取った側では、これをまた MIDI のバイト列に組み直して音源へ渡す。
**同じ値が続いても捨ててはいけない**。RPN/NRPN は `CC101=0, CC100=0, CC6=n`
のように同じ値を続けて送ることに意味があり、間引くとピッチベンド幅が化ける。

同じ時刻に複数届いたときは、パラメータ変化を先、イベントを後に流す。
「音量を決めてから発音」の順になる。

### 表に従わないホスト

表のとおりに渡してこないホストがある。VSTHost 1.58 はプログラムチェンジを
パラメータではなくイベント（`DataEvent`、システムエクスクルーシブ扱い）に入れ、
しかも 2 byte の `C0 xx` を 3 byte の `C0 xx 00` に詰めて渡してくる。
余分な `00` をそのまま音源へ流すと、走行状態（ランニングステータス）の
データバイトになって続けてプログラム 0 が入り、音色がグランドピアノに戻る。

そこで `DataEvent` の中身の頭がチャンネルのステータス（`80`-`EF`）なら、
システムエクスクルーシブではないと見て、そのメッセージの決まった長さだけ取り出し、
後ろの詰め物は捨てる。頭が `F0` か、途中の切れ端（データバイト）なら今までどおり
バイト列のまま流す。`build/vst3probe.exe ... --data-midi` がこのホストのまねをする。

## 目に見えるつまみ

画面が無いので、ホストの汎用パネルに出るのはこの 2 本だけ。
MIDI 用の 2096 本は隠してある。

| 名前 | 中身 |
|---|---|
| `Output` | 出力レベル 0-100%。音源の外で掛ける。急に変えても跳ねないよう 1 サンプルずつ寄せる |
| `Status` | `Booting` / `Ready` / `No ROM`。読むだけ。**鳴らないときはここを見る** |

`Status` があるのは、起動待ちの数秒と ROM が無いときの無音を
見分ける手段が他に無いから。

## 標本化周波数

MU2000 は 44100Hz でしか動かない。ホストがそれ以外なら、窓関数付き sinc
（64 タップ、ブラックマン窓）で変換する。44100 ちょうどのときは変換を通さない。

音源側は「必要な先の音」をその場で作れるので、変換に先読みの遅れは無い。
`getLatencySamples()` は 0 を返す。

## 複数挿したとき

ROM は読むだけなので、DLL の中で 1 組だけ持ち、何枚挿しても分け合う。
36MB × 枚数にはならない。誰も使わなくなれば解放される。

音源そのものは枚数ぶん動く。1 枚あたり CPU 40% 前後なので、
この機械（実測）では 4 枚同時までは余裕があった。

DAW ごとの使い方:

| DAW | マルチティンバー | 書いたもの |
|---|---|---|
| Cakewalk Sonar | **できる**。MIDI トラックごとに送り先（A / B のバス）とチャンネルを選ぶ。32 パート | [doc/sonar.md](sonar.md) |
| Reason | できない。1 トラック 1 楽器でパート 1 だけ。MIDI の輪で PC ごと固まった件も | [doc/reason.md](reason.md) |

## MIDI の入力バスは 2 本

実機の MIDI IN A / B と同じく、**入力バスを 2 本**持っている。

| バス | 届く先 |
|---|---|
| `MIDI In A (Part 1-16)` | パート 1-16。ふつうに挿せばここに繋がる |
| `MIDI In B (Part 17-32)` | パート 17-32 |

B を使うかどうか、どう見せるかは DAW による（2 本目のバスを選ばせない DAW も
ある）。CC・ピッチベンド・プログラムチェンジは VST3 ではパラメータとして届くので、
口ごとに 16ch × 131 本ずつ持っている。番号は A が 0-2095（前から同じ）、B が
8192-10287。出力レベル（4096）と状態（4097）の番号も前から変えていない。

## A/D INPUT（音声の入力バス）

サンプリングで録る音を入れる口として、**補助の音声入力バス `A/D Input`**（ステレオ）を 1 本持っている。
左が AD1、右が AD2。DAW ではサイドチェーンの入力として見えることが多い。繋がなければ無音。
ホストの周波数が 44100Hz でなければ、中で 44100Hz に直してから使う。
サンプリングの録音と A/D パートに使う。A/D パートの音量は XG の初期値が 0 なので、鳴らすには音量を上げる（XG のパラメータ 10 00 0B、AD2 は 10 01 0B）。入力のエフェクトもふつうのパートと同じに掛かる。

## SmartMedia

パネルの**カードの差し込み口**（左下）をクリックすると、gui.exe と同じ品書きが出る（新しく作って差す / 差す / 抜く）。
カードの中身は PC のファイル（`.img`、gui.exe と同じ形）で、firmware が書いたところは画面を開いている間 2 秒ごとと、
プロジェクトを保存するとき・プラグインを外すときに書き戻す。プロジェクトには**ファイルの場所だけ**を覚え（中身は 16〜128MB あるので入れない）、
開き直すとそのファイルを差す。PC との出し入れは `tools/smcard.py`（doc/gui.md）。

同じファイルを 2 枚のプラグインや gui.exe で同時に差さないこと（書き戻しがぶつかって、どちらかの書き込みが消える）。

## 確かめ方

`make probe` は DAW 無しでプラグインを読み込む小さなホスト。
MIDI ファイルを渡すと、VST3 の経路を通して WAV に書き出す。

```
build/vst3probe.exe build/S-MU2000.vst3/Contents/x86_64-win/S-MU2000.vst3
build/vst3probe.exe <上の DLL> song.mid out.wav --rate 48000 --block 128
build/vst3probe.exe <上の DLL> --torture
```

MIDI ファイルの口（`FF 21`）はそのままバスの番号として渡す。`--one-bus` を
付けると全部 A のバスに流す（B が効いているかを比べる用）。`port_b` の曲で
比べると、2 本のときは `render.exe` との包絡線の差が 1.0%、`--one-bus` では 24.6%。

`--torture` はホストがやりそうな乱暴を一通りやる。初期化せずに捨てる、
initialize/terminate を往復する、22050 から 192000 まで全部の周波数、
長さ 0 の process、バス無し、64bit 指定、setActive をばたばた切り替える、
パラメータ 4194 本の問い合わせ、2 口ぶんの MIDI の割り当て、4 枚同時。DAW ごとに呼び方が違うので、
落ちないことをここで先に確かめておく。

`render.exe`（VST3 を通さない書き出し）と突き合わせた結果:

| ホストの周波数 | 50ms 区間の一致（振幅 10% 以内） | 参照が鳴ってこちらが鳴らない区間 |
|---|---|---|
| 44100 | 98.3% | 0 |
| 48000 | 98.1% | 0 |

サンプル単位では一致しない。MIDI の届く時刻が数サイクルずれると SWP30 の
どのチャンネルに割り当てられるかが変わるため。鳴っている音は同じ。

## 画面

実機のフロントパネル風の画面が付いている（`IPlugView` を自前で実装し、
ホストの親ウィンドウに子ウィンドウを 1 枚作る）。中身は gui.exe と同じ。
[doc/gui.md](gui.md) を見よ。

## まだ無いもの

- 個別出力（実機の 6 系統）。今はステレオ 1 系統だけ
- 64bit 浮動小数の処理（`kSample32` のみ）

## macOS

macOS 版も同じ中身で作れる。バンドルの形と口の名前だけが違う。

```
make vst3                    build/S-MU2000.vst3 を作る
make probe                   ホストのふりをして読み込む
make install-vst3            ~/Library/Audio/Plug-Ins/VST3 へ複製

build/vst3probe build/S-MU2000.vst3                  素性を見る
build/vst3probe build/S-MU2000.vst3 song.mid out.wav 鳴らす
build/vst3probe build/S-MU2000.vst3 --torture        乱暴に扱う
build/vst3probe build/S-MU2000.vst3 --view 20        画面を出す
```

バンドルは `Contents/MacOS/S-MU2000`（実行体）と `Contents/Info.plist`。
ホストは `dlopen` ではなく `CFBundle` で開き、`bundleEntry` を呼ぶ。
画面は `src/vst3/view_mac.mm`（`NSView`）で、ホストの親ビューの中に 1 枚
足す。描画は gui と同じ `compat/gdi_mac.cpp` を通るので、**panel.cpp は
Windows 版と同じソース**のまま。

ROM は `S_MU2000_ROMS`、バンドルの隣の `roms.txt`、
`~/Library/Application Support/S-MU2000/roms` の順に探す。

同じ engine を使った Audio Unit（AUv2, `aumu`）も作れる（`make au`）。
そちらは `src/au/plugin.cpp`。

移植の全体は [porting-macos.md](porting-macos.md) にまとめてある。
