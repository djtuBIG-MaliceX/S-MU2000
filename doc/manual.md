# S-MU2000 使い方の手引き

S-MU2000 を**はじめて使う人**向けの通しの手引き。用意するもの → 作る → 単体で鳴らす → 画面を触る →
DAW に挿す、の順に並べた。中の作りや調べた経過は書かず、くわしい話はそれぞれの文書へ案内する。
英語版は [manual.en.md](manual.en.md)。

> ヤマハとは無関係の非公式なプロジェクト。Yamaha・MU2000・XG はヤマハ株式会社の商標。

## 1. 用意するもの

| もの | 中身 |
|---|---|
| MU2000（実機） | ROM を取り出すのに要る。**ROM は配っていない**ので、自分の実機から取り出す |
| PC | Windows（x86-64）か macOS（Apple silicon）。MU2000 のまるごとを動かすので CPU を使う（16 パートが鳴りっぱなしの曲で実時間の 21% ほど。Ryzen 7 9700X）。**この割合は機械しだい**で、1 コアの速さに反比例して増える。古い機械では 2〜3 倍になる |
| USB ケーブル | 波形 ROM を取り出すときに使う（MIDI インターフェースは要らない） |
| 仮想 MIDI ケーブル | 単体版を外のシーケンサから鳴らすとき。Windows なら loopMIDI（[domino.md](domino.md)） |

**実機から取り出したもの（ROM、ファームウェア、それを含む `.ydl`）は、どこにも載せない・配らない。**
不具合の報告はハッシュ値・ログ・MIDI ファイル・録音で足りる。くわしくは
[README の注意書き](../README.ja.md#実機由来のデータは配らない載せない)。

## 2. ROM を用意する

要るのは 2 つ。手順と道具は [dump/README.md](dump/README.md)。

| ROM | 手に入れ方 |
|---|---|
| プログラム ROM（4MB） | **取り出さなくていい。** ヤマハの更新プログラム `mu2r1_uw.zip` から `tools/dump/ydl_extract.py` で組み直す |
| 波形 ROM（32MB） | USB ケーブル 1 本で約 36 分。自作のダンパを実機に書き込んで読み出す（純正の更新プログラムでいつでも戻せるが、書き換えなので自己責任で） |

できたものを 1 つのフォルダ（以下「rom フォルダ」）に置く。

```
roms/
  mu2000_flash.bin        プログラム ROM
  dump/xv364a0.ic49 ほか  波形 ROM 8MB × 4
  standin/sin-table.bin   MEG が使う sin 表
```

## 3. 作る

Windows は MSYS2 の MINGW64 環境の g++ と make、macOS は Apple の clang++ と make を使う（C++20）。
Linux でも `make` が通るが、いまは画面の要らない道具だけ（[linux.md](linux.md)）。

```bash
make
```

`build/` に次ができる。

| できるもの | 中身 |
|---|---|
| `build/gui.exe` | 単体版。実機パネル風の窓で鳴らす（いちばんよく使う） |
| `build/S-MU2000.vst3/` | VST3 プラグイン |
| `build/S-MU2000.clap` | CLAP プラグイン（Windows） |
| `build/live.exe` | 窓を出さずに MIDI を受けて鳴らす |
| `build/render.exe` | MIDI ファイルを WAV に書き出す（**標準 MIDI ファイル（SMF）の形式 0・1 だけ**。RCP や XWS は先に SMF に直す） |

Windows の exe は MSYS2 の DLL に頼らないので、素の PowerShell やエクスプローラからも起動できる。
macOS のビルドの違いは [porting-macos.md](porting-macos.md)。

## 4. 単体で鳴らす（gui.exe）

### 起動する

```bash
build/gui.exe C:\path\to\roms
```

数秒で LCD に `◀000▶001 GrandP #01` のような演奏画面が出る。これが実機の電源を入れたときと同じ状態。
**2 回目からは起動が速い**（1 度起動し切った姿を覚えておいて読み込む）。

### MIDI の入口を選ぶ

パネルに描いてある **`MIDI IN A` のジャックを左クリック**するか、窓のどこかを右クリックすると品書きが出る。
動かしたまま選び直せる。

| 口 | 鳴らすパート |
|---|---|
| MIDI IN A | 1-16 |
| MIDI IN B | 17-32 |
| MIDI IN C | 33-48（実機では USB だけの口） |
| MIDI IN D | 49-64（同じく） |
| MIDI OUT | MU2000 が自分で送り出すもの（ダンプの返事など） |
| MIDI THRU A / B | 受けたものを外へそのまま流す（実機と聴き比べるときに使う） |

Domino などから鳴らすときは loopMIDI で口を作り、シーケンサの出口とこちらの入口に同じ口を選ぶ
（[domino.md](domino.md)）。選んだものは**名前で**覚えるので、次からは選ばなくてよい。

### 音の出口と待ち時間

音の出口は起動のときに `--audio "名前の一部"` で選ぶ（名前は `build/gui.exe --list` で見る）。
一度選ぶと覚える。

| 付けるもの | 効き目 |
|---|---|
| `--exclusive` | 音の出口を独り占めする。待ち時間がいちばん短い（実測 16ms）。ほかのアプリは音を出せなくなる |
| `--latency 10` | 溜めの長さ（ミリ秒）。音が途切れるなら伸ばす |

オーディオインターフェースは 44100Hz・バッファ 256 サンプルにしておくと、変換も遅れも少ない。
くわしくは [README の「待ち時間」](../README.ja.md#待ち時間)。

### MIDI ファイルを流す

MIDI ファイルを**窓に落とす**か、`--play 曲.mid` を付けて起動する。止めるのはカードの差し込み口の品書きの
「止める」。4 口ぶんの曲はトラックの口の指定（`FF 21`）に従って A〜D に振り分ける。

### 設定は残る

MU2000 の設定（ユーティリティ、マスターボリュームなど）は、実機の電池で保たれる RAM と同じく、
**閉じても次の起動に残る**。工場出荷状態に戻すには、右クリックの品書きの「工場出荷状態に戻す...」か、
`--factory` を付けて起動する。

## 5. パネルを触る

実機のフロントパネルと同じように触れる。LCD には firmware が書いたものがそのまま出る。

| もの | 触り方 |
|---|---|
| ボタン | クリック。キーボードでも押せる（下の表） |
| 大きなダイヤル | **ホイールで回す**か、掴んで上下に動かす。VALUE −/+ と同じ働き |
| VOLUME | 掴んで動かすか、上でホイール。音源の外で掛ける最後の音量 |
| カードの差し込み口（左下） | SmartMedia を作る・差す・抜く、MIDI ファイルの再生と停止 |
| A/D INPUT のジャック | サンプリングで録る音の入口（録音デバイス）を選ぶ |
| PHONES のジャック | 音の出し方（デジタル / アナログ）を選ぶ |

| キー | ボタン |
|---|---|
| `A` `E` `U` `F` | PLAY・EDIT・UTIL・EFFECT |
| `Q` `M` | SEQ・SAMPLING |
| `S` | MUTE/SOLO |
| `[` `]` | PART −/+ |
| `-` `=` | VALUE −/+ |
| `,` `.` | SELECT ◀ ▶ |
| `Enter` `BackSpace` | ENTER・EXIT |
| `Z` `X` | AUDITION・SELECT |
| `F2` `F3` | エディタの窓・一覧の窓（窓の最上段のボタンでも開ける） |

SmartMedia のカードは PC のファイル（`.img`）で、`tools/smcard.py` で WAV などを出し入れできる。
**録った音を MIDI の音色として鳴らすまでの手順は [sampling.md](sampling.md)**。
パネルの絵そのもの（位置・色・SVG の絵）は作り直さずに直せる（[panel-editing.md](panel-editing.md)）。
画面のくわしい話は [gui.md](gui.md)。

## 6. PC で触る窓

パネルとは別に、マウスとキーボードで XG の値を触る窓がある。閉じても隠すだけで、開き直すと同じ姿で出る。
くわしくは [pc-editor.md](pc-editor.md)。

| 窓 | 開き方 | 使いどころ |
|---|---|---|
| **一覧** | F3・右クリック | 曲を流しながら、全パートの音色・音量・エフェクトを見渡して整える |
| **パートの音色** | 一覧で VIB・FILTER・EG・EQ の絵をダブルクリック | 1 つのパートの音色を選び、ビブラート・フィルタ・EG・EQ を絵でつまんで作る。PC のキーボードで弾ける |
| **インサーションの設定** | 一覧で INS の印やマスターの INS 1-4 をダブルクリック | インサーション 1-4 の種類ごとのパラメータを、エフェクターのようなつまみで触る |
| **マスター** | 一覧のマスターの行の MASTER の名前か MASTER EQ の絵をダブルクリック | マスターボリューム・移調、リバーブ・コーラス・バリエーションの種類と戻り、マスター EQ |
| **エディタ** | F2・右クリック | 表とつまみの仮の形（作り直す予定） |

### 一覧

1 行が 1 パート。VOL・PAN・VAR・CHO・REV は**ドラッグ・ホイール・ダブルクリックで打つ**で変えられる。
パート名の欄を右クリックすると音色、INS 欄を右クリックするとエフェクトを掛ける・外す・種類を選ぶ。
INS の印（`1`-`4`、`V`）は**ドラッグして別のパートに落とすと移る**。M でミュート、S でソロ。
鍵盤はマウスで弾ける。上の右端に同時発音数（`発音 112/128 (M:64, S:48)`）と CPU の負荷が出る。
表示の大きさは上の `-` `+`。

### パートの音色

* 左で分類と音色を選ぶ。替えるたびに 1 秒だけ試聴の音が鳴る
* 右の 4 つの絵の点をつまむ（VIB は速さと深さ、FILTER はカットオフとレゾナンス、EG はアタック・ディケイ・リリース、EQ は周波数とゲイン）。絵の下の棒でも合わせられる
* 上のペインにエフェクトの種類、VOL〜REV の棒、鍵盤
* **鍵盤を右クリックすると緑の目印**が付き、試聴はその鍵で鳴る
* 鍵盤の左端の溝は**モジュレーションホイール**。カーソルを載せてホイールか上下にドラッグ
* **PC のキーボードで弾ける**: `A` `W` `S` `E` `D` `F` `T` `G` `Y` `H` `U` `J` `K` `O` `L` `P` `;` が C から半音ずつ。`Z` / `X` でオクターブを下げる・上げる
* 一覧で別の行をクリックすると、この窓もそのパートに替わる

### インサーションの設定

上の帯で INS 1-4 を切り替え、種類と掛けるパートを選ぶ。つまみは上下にドラッグ（Shift で細かく）、
ホイール、ダブルクリックで数を打つ。EQ を持つ種類は特性の絵が出る。
種類の品書きは分類（リバーブ・ディレイ・歪み・EQ…）ごとに印の絵が付いている。

### 説明と言語

窓の上の「説明を出す」を入れると、カーソルを載せた項目が何に効くのかを出す。言語は日本語と English。

## 7. DAW に挿す（VST3・CLAP・AU）

中身は gui.exe と同じで、**画面も同じ**（パネルを右クリックすると一覧などの窓が開く）。
くわしくは [vst3.md](vst3.md)。

### 置く

```bash
make install-vst3
```

```bash
make install-clap
```

| 形式 | 置き場（Windows） |
|---|---|
| VST3 | `%LOCALAPPDATA%\Programs\Common\VST3`（自分だけ）か `C:\Program Files\Common Files\VST3`（全員） |
| CLAP | `%LOCALAPPDATA%\Programs\Common\CLAP` か `C:\Program Files\Common Files\CLAP` |

macOS は VST3 を `~/Library/Audio/Plug-Ins/VST3` に、Audio Unit は `make au` で作る。

### ROM の場所を教える

ROM は 36MB あるので複製せず、**場所を 1 行書いた `roms.txt`** を置くのが楽。

| 形式 | `roms.txt` の置き場 |
|---|---|
| VST3 | バンドルの `Contents/Resources/roms.txt` |
| CLAP | `S-MU2000.clap` のすぐ横か、`%LOCALAPPDATA%\S-MU2000\roms.txt` |

```
C:\path\to\roms
```

環境変数 `S_MU2000_ROMS` でも渡せる。

### 挿したら

* **挿してから数秒は鳴らない**。実機の電源を入れたときと同じ起動待ちで、その間の MIDI は溜めておいて後で流す。
  パラメータ `Status` が `Booting` → `Ready` になれば鳴る（`No ROM` なら ROM が見つかっていない）
* MIDI の入力バスは **4 本**（`MIDI In A (Part 1-16)` 〜 `MIDI In D (Part 49-64)`）。トラックごとに送り先を選ぶ
* `Output` が出力レベル
* A/D INPUT 用に補助の音声入力バス（サイドチェーンとして見える）がある

### 保存とオートメーション

* プロジェクトを保存すると、**音色もエフェクトも画面で変えた値も**まるごと残る
* パートの音量・パン・送り・フィルタ・EG・ビブラート・EQ（64 パート × 19 本）、マスターの値（27 本）、
  インサーション 1-4 のパラメータ（4 × 16 本）が**名前付きのパラメータ**として見え、オートメーションで描ける
* 画面で触った値もオートメーションとして記録できる（VST3・CLAP）

名前と番号の一覧は [automation.md](automation.md)。DAW ごとの話は [sonar.md](sonar.md)・[reason.md](reason.md)。

### plugin.ini

`%LOCALAPPDATA%\S-MU2000\plugin.ini`（macOS は `~/Library/Application Support/S-MU2000/plugin.ini`）に書く。
挿し直すと効く。

| 行 | 効き目 |
|---|---|
| `usb=0` | USB の口（A〜D）ではなく DIN の口（A・B、32 パート）で起動する |
| `threaded=0` | 2 つ目の音源チップをプラグイン自身の糸で回さず、DAW の音声の糸の中で回す |

## 8. 設定の置き場

Windows は `%LOCALAPPDATA%\S-MU2000\`、macOS は `~/Library/Application Support/S-MU2000/`。

| ファイル | 中身 |
|---|---|
| `gui.ini` | gui.exe の MIDI の口・音の出口・VOLUME・差していたカードなど |
| `editor.ini` | PC の窓の表示の大きさ・説明の言語・試聴の鍵など |
| `plugin.ini` | プラグインの起動のしかた（上の表） |
| `nvram\` | MU2000 の設定（実機の電池で保たれる RAM）。gui.exe と live.exe が書き、プラグインは読むだけ |
| `boot\` | 起動し切った姿の写し。消しても次の起動で作り直す |
| `log.txt` | プラグインの記録。ROM を探した場所など |
| `roms.txt` | プラグインが探す ROM の場所（CLAP など） |

## 9. 困ったとき

| ようす | 見るところ |
|---|---|
| プラグインが鳴らない | `Status` パラメータと `log.txt`。`No ROM` なら `roms.txt` の場所を確かめる |
| 挿してすぐ弾くと鳴らない | 起動待ち（数秒）。実機と同じ |
| 曲の音色が全部ピアノになる | 起動し切る前に音色の指定が届いた。起動を待ってから流す |
| パート 33-64 が鳴らない | USB の口で起動しているか（gui.exe は `--host-midi` を付けない、プラグインは `usb=0` を書かない） |
| 「MIDI が多すぎるので捨てた」と出る | DAW と loopMIDI で MIDI の輪ができている。THRU の繋ぎを見直す |
| 口を開けない・起動の途中で止まったように見える | loopMIDI やドライバが固まっている。loopMIDI を起動し直すか機器を挿し直す |
| 音が途切れる | `--latency` を伸ばす。インターフェースのバッファと周波数（44100Hz）を見直す |
| 設定をまっさらにしたい | 右クリックの「工場出荷状態に戻す...」か `--factory` |

不具合は [Issues](https://github.com/tarboh/S-MU2000/issues) へ。そのとき ROM やファームウェアは添付せず、
ハッシュ値・`log.txt`・MIDI ファイル・録音を付ける。
